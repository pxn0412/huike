### 自动入库：跑通那晚踩的 3 个坑（别再踩）

1. **要用旧版 `lke`（2023-11-30）这套接口**。新版 `adp.tencentcloudapi.com/2026-05-20` 里**没有 `SaveDoc`**；它的 `ImportDocList` 要一个"文件管理服务"给的 `FileId`，而**公开 API 里没有文件上传接口**（121 个接口全查过），传纯数字 ID 只会报 `describe file failed: KeyInvalidParam`。
2. **COS 签名的 `sign_key` 必须用 `hexdigest()`**（不是 `digest()`）——照官方 COS SDK（`qcloud_cos/cos_auth.py`）写的；用 `digest` 永远 `SignatureDoesNotMatch`。签名里的 path 用**未转义原文**。
3. **知识库 ID 用"应用 ID"那个值：`2100783876846755776`**（ADP 里应用与默认知识库**共用同一个 ID**）。之前 `.env` 里的 `2101264937098770560` 是错的 → 所有知识库接口都报 `FailedOperation 450011 应用不存在`。

另外 `DescribeStorageCredential` **必须**带 `BotBizId` + `FileType` + `TypeKey=offline` + `IsPublic=false`：不带 `FileType` 只给下载权限，写 `/public/...` 路径会 `AccessDenied`；带全才会返回可写的 `UploadPath`（形如 `/corp/<uin>/<知识库 ID>/doc/xxx.md`），这个 `UploadPath` 就是后面 `SaveDoc` 的 `CosUrl`。

**验收证据**（2026-09-19 23:5x）：测试文档 SaveDoc 返回 `DocBizId 2101347259918114624` → 知识库状态"导入完成" → 用 `DeleteDocList` 删除 → 库内恢复为通知 + 海报 2 份。

**平台的去重行为（同晚实测，重要）**：`python adp.py --all` 重传已有资料时，COS 上传成功、`SaveDoc` 被拒：

```
FailedOperation 450020-文档已存在，重复文档名称:慧科杯-知识库上传-海报2026-09.md，文档ID:2101283372262809408
```

两条结论：① **重复提交是安全的**，不会在库里产生重复文档；② 去重是**按文件名**，所以**资料出新版本时不能沿用同名文件**（同名会被拒），要给新版本换名字（例如 `…-2026-09-20.md`），才能两版并存、回答时并列展示。

**本地网站也接上了（2026-09-20）**：在网站里"确认添加"后会自动做同一套上传（`store.sync_knowledge_base` → `adp.push_document`），状态写在资料元数据 `metadata.knowledge_base` 里；比赛空间显示"知识库：已进知识库（N 块）· 文件名"，失败的可以点"重新上传到知识库"（`POST /api/documents/<id>/sync`）。知识库文件名 = `标题前 60 字 + 发布日期`（因为平台按名字去重）。想关掉自动上传：`.env` 里加 `ADP_AUTO_UPLOAD=0`。

补充一条平台脾气：文档处于**"学习中"状态时不允许删除**（`450041-文档不允许删除`），要等状态变成"导入完成"再删。

### 网页问答改成由智能体回答（2026-09-20）—— 以及串比赛这个坑

新增 `website/agent.py`：网页的"提问"优先调用**已发布的智能体**（`ADP_APP_KEY` / `ADP_CHAT_URL`），这样网页里的回答与评委扫码的是同一个（`mode=agent`，附平台引用与用时）。智能体不可用时返回 `mode=agent_failed` 并只展示本地原文，**绝不假装回答**；没配智能体时才退回本地 DeepSeek（`mode=ai`），再没有就只给关键词检索（`mode=keyword_evidence`）。

**踩到的坑（重要）**：知识库里同时存在多场比赛的资料时，智能体会**串比赛** —— 问慧科杯"必须有指导老师吗"，它引用了《中国大学生计算机设计大赛》的规定回答"必须有指导老师"。

- **网页侧已修**：提问时自动把当前比赛写进提示词（`【当前比赛：X】只依据这场比赛资料回答，没有就直说，不许引用其他比赛`）。复测同一问题 → 回答"这场比赛资料中没有找到" ✅
- **平台侧还要做**：评委直接扫码问智能体时不受网页约束，所以**提示词里也要加同样的规则**（见下方，建议贴到 ADP 提示词开头）：

```
【比赛范围（必须遵守）】
知识库里可能同时有多场比赛的资料。
1. 问题里已指明比赛（或出现“当前比赛：X”）→ 只用 X 的资料回答；
2. 没指明比赛 → 先反问“你问的是哪场比赛？”，或在回答开头写明“以下依据来自《X》”；
3. 绝不能用 A 比赛的资料回答 B 比赛的问题；这场比赛资料里没有时，直接说
   “这场比赛资料中没有找到”，不要拿别的比赛替代。
```

更彻底的做法（未来）：给文档打"比赛"标签，检索时按标签过滤；或一场比赛一个知识库 + 一个智能体。

## 三、五条关键结论（最容易忘）

1. **答不准的第一嫌疑不是提示词**，是检索设置：平台"文档检索匹配度"默认只有 **0.2**、"文档召回数量"默认 **5**，等于不过滤。先调到 **0.4 / 8** 并打开重排序。
2. **新旧资料不互相覆盖**。9 月海报**没有**声明替代 6 月通知（产品规格 `04-比赛资料进入系统.md:199` 明确禁止这么理解），所以两份不一致时**并列展示**，并提示以官方最新通知或赛事群公告为准。**不许按"日期更新的赢"处理。**
3. **冲突按"事实字段"判定，不按文档判定**。海报只覆盖 AI 赛道；PBL 赛道的 6/20 报名、6/24 提交、7/1 答辩仍以 6 月通知为唯一依据。
4. **块内只放一行标题**（含页码与赛道），字段放 yaml / 平台元数据。理由：反复出现的"比赛名/版本"会稀释正文区别度。
5. **27 块先冻结，先测再决定拆不拆**。要拆就拆成"总览块 + 单项块"双粒度，不要单向切碎。
