## 一、总原则（你定的）

> **初赛不按"最终成品架构"做，按"视频里能证明项目价值的最小闭环"做。**

- 交付物：≤10 分钟演示视频 + PPT + 在线访问链接/二维码 + 项目开发说明文档。
- 要证明的三件事：**① AI 看得懂比赛 ② AI 看得懂学生 ③ 两边信息最后真的用起来（→ 招募）**。
- 不再往"我的队伍 / 申请加入 / 消息系统 / 提醒 / 复杂多智能体路由"扩。

## 二、页面（登录页 + 5 个主页面 + 上传）

**入口 = 登录页**：邮箱或手机号 + 密码（**注册与登录分开**，同一张卡片两个 tab，密码本地加盐存储）；
**没登录时全部 `/api` 接口返回 401**，所以这不是门面，是真的挡在门口。

```text
登录页 ──► 首页 / 比赛库（含「我的比赛」区块）
          ├─ 比赛详情 ── 智能体 A：**一页到底**（提问气泡 / 回答卡片 / 「依据与原文」一块，原文在最下面；资料收成一行折叠）
          │             ＋ 资格逐项核对 ＋ ⭐关注 ＋ "这场比赛招募（N 条）→"
          ├─ 我的竞赛画像 ── 智能体 B：**先对话** → 点「整理成画像草稿」→「确认并保存」才写库
          ├─ 队伍招募 ── 招募广场 / 我的招募 / 详情 / 发布·编辑
          ├─ 添加比赛资料
          └─ 侧栏账号 ── 「显示名称 + 退出登录」
```

**两个智能体藏在两个业务页面里**（用户不需要知道"该找哪个 AI"）：
- A 住在**比赛详情**；B 住在**我的竞赛画像**。
- 比赛页在需要个人信息时**临时调用 B 的能力**（生成一条画像草稿 →【加入我的画像】/【去画像页详细编辑】），
  但**全系统只有一份画像**，两个页面只是不同入口。

## 三、演示视频的 8 幕主故事 + 1 段能力展示

| 幕 | 屏幕 | 用户动作 | 系统表现 |
| --- | --- | --- | --- |
| 1 | 登录 | 选身份 + 填名字 | 进来就是"登录" |
| 2 | 比赛库 | 浏览 3 场比赛 | 一眼看出是"管比赛的平台" |
| 3 | 比赛详情 | ⭐ 关注 → 问"一个人能参加吗" | A 引原文回答 + 来源；首页随后出现「我的比赛」 |
| 3b | 比赛详情 | "我大二，数字媒体专业，一个人，能参加吗" | **资格逐项核对**：✅满足 / ❌不满足 / ⚪资料未规定 / ❓缺少信息 + 每项来源 |
| 4 | 比赛详情 | 问"那我这种情况适合怎么准备" | A 缺个人信息 → 就地调用 B → 画像草稿 →【加入我的画像】 |
| 5 | 我的画像 | 补一句"还做过 PPT 和演示视频" | B 追问"是你本人做的还是团队共同完成？"→ 更新草稿 → 保存 → 打开"允许展示" |
| 6 | 比赛详情 | "根据我的情况，我可以先做哪些部分" | A + 画像：官方要求与已记录经历**并列**，明确说"不能据此判断你能独立开发"，并提示可找队友 |
| 7 | 比赛详情 | "那我想找个开发的队友" | 不给推荐，提示"可以发布一条招募 →" |
| 8 | 队伍招募 | 发布招募 | 跳到「我的招募」✅ 发布成功 → 切「招募广场」同一条公开可见 |
| 9 | 添加比赛资料 | 上传 PDF → 确认 | 识别比赛名/届次/发布方/赛道 |
| 10 | 比赛库 → 新比赛 | 点进去问"这个比赛几个人参加" | A 依据刚上传的资料回答 |

## 四、闭环补点（你逐个点出来的）

| 缺口 | 定案 |
| --- | --- |
| 发完招募就找不到 | 招募页两个区域：**招募广场**（别人的）/ **我的招募**（查看·编辑·结束招募，状态只有 招募中/已结束） |
| 比赛页看不到本场招募 | 比赛页显示 **"这场比赛招募（N 条）→"**；**N 由普通数据库查询得出，不是 A 算的** |
| 下次回来找不到比赛 | **⭐ 关注比赛**（必须用户主动点）→ 首页「我的比赛」区块 + 用户菜单"我关注的比赛" |
| "我加入的队伍" | **不做**：系统不追踪站外联系结果，做了是**假闭环**（等真做申请机制时再放**招募页**，不放画像页） |
| 所有"我的东西"找得到 | 轻量**用户菜单**（不做个人中心、不做老师后台） |
| 比赛页太满、找不到回答 | **通知和问答合成一页**：提问是「我」的气泡（更显眼）、回答是「AI」卡片；用时 / 引用 / 本地原文片段**收在回答后面同一块「依据与原文」里，原文片段放最下面**；资料不再单独占一栏，收成标题下面一行折叠；**答完自动停在最新一轮结尾**，不用从头往下滑 |
| 招募详情看不到"发布者是谁" | 详情页展示**发布者的已确认画像**（专业/年级/做过什么/希望参与/在学什么）：**默认展示、没有"是否公开"开关**（露不露由"发不发招募"决定）；没填过就明说"发布者还没有填写竞赛画像"；广场卡片上标一句"已填写画像"；仍不做等级/评分 |

## 五、身份：**登录页（邮箱 / 手机号）**，账号就是身份

- 入口先注册或登录：**邮箱或手机号 + 密码**；注册只创建、登录只校验（没注册过会提示去注册），密码只存 pbkdf2 加盐摘要（标准库）。
- **账号 ↔ 本机身份一一对应**：登录成功后服务端把身份 Cookie 换成账号绑定的身份，
  于是**换台电脑/换个浏览器登录同一账号，画像、招募、上传的资料都还在**。
- 首次登录会把「这个浏览器之前匿名用出来的东西」绑到新账号上 —— 老数据不丢、不搬走。
- **未登录 = 什么都读不到**：除 `/api/status` 与 `/api/auth/*`，其余接口一律 401（真门禁，不是前端遮挡）。
- 不再有「学生 / 老师」自选身份：去掉假的身份标签，只保留账号显示名（用于"发布者：小张"这类展示）。
- ⏸️ **关注比赛 / 我的比赛**：Codex 说按你最新要求取消了，**待你确认**（`follows` 表和 store 方法仍在，没接入口）。


## 六、资格核对（优先级最高的一屏）

**固定契约：四态 + 每项带来源**

```text
✅ 满足     专业条件：官方明确"专业不限"            [来源：通知 第 1 页]
❌ 不满足   （有明确不符时）
⚪ 资料未规定 年级条件：当前资料未找到年级限制        [来源：—]
❓ 缺少信息  学校身份：资料要求"本校在校生"，需你确认  [来源：通知 第 2 页]

因此：目前不能完整确认报名资格，但"专业"与"队伍人数"两项已有依据支持。
```

规则：**不许出现"整体上你能/不能参加"的结论句**；只给"哪几项有依据、哪几项无法确认"；
冲突资料有明确废止/修改关系 → 说明替代关系，没有 → 并列保留。不预测获奖、不评价能力、不推荐队友。

## 七、画像（第 2 步重点）：**AI 生成 ≠ 保存**

- **草稿只在前端**：用户点「确认并保存」才写库；**不建草稿表、不需要确认令牌**。
- **结构只三类**（不是简历）：

```text
专业 / 年级（背景一行）
做过什么 ｜ 本人负责什么
希望参与什么
正在学习 / 希望尝试什么
```

- **禁止**技能等级 / 熟练度 / 星级 / 评分（会滑向 AI 能力评分）。
- **保真四条**（已在平台侧实测通过）：
  1. "跟教程做过一次"→ **不得**升级成"精通"；
  2. 用户**明确自述**"我精通 Python"→ **忠实保留**（AI 只能不升级，不能反过来纠正用户）；
  3. 团队成果只写**本人负责的部分**；含糊时只追问一句："这件事里你本人主要负责什么？"；
  4. 不评价、不打分、不排名、不判断资格。
- **修改画像**：输入 = `【当前已保存画像】+【当前编辑草稿】+【对话记录】+【本轮用户消息】`，输出 = 完整草稿 + **【本次修改】**；
  **其余条目原样保留**，不能重新生成把原来的弄丢。
- **2026-09-20 晚修订（交互）**：画像页拆成**对话区 + 草稿区**。日常聊天只回话（`reply` 永远有值、不生成草稿），
  点「整理成画像草稿」才是"网站发起的整理任务"（只出草稿）。对话消息落库（`profile_messages`），刷新/换设备不丢；
  草稿仍然只在前端、`/api/profile/save` 仍然只由"确认并保存"触发。平台的 B 提示词已按此口径交给用户，见 `2026-09-20-当前进度总结.md` §5。
- 页面固定文案：「以下内容由本人填写或确认，不代表学校认证」。
- **2026-09-20 晚修订（公开开关）**：**删掉"是否公开"**。主画像**只给自己看**，不进任何对外展示。
  `profiles.visibility` / `recruitments.show_profile` 两个旧列留在库里但代码不再读写。
  （原计划"招募详情改展示子画像"**随后也撤回**，见七之二。）

不落库也不需要落库——要留下的内容由本人写进那四栏。

## 七之三、招募协助：在招募表单里「和 AI 一起完善」（2026-09-20 晚）

写不出「项目想法」时，不用另做一个子画像页面：**在现有招募表单里加 AI 协助**。

```text
发布招募页（左右两栏）
  左：招募表单（对应比赛 / 标题 / 项目想法 / 希望队友参与 / 人数 / 联系方式）
       └ 「项目想法」旁边一个按钮：和 AI 一起完善
  右：「和 AI 一起完善」面板
       ① 比赛助手 · 依据：这场比赛的要求（带来源，可「重新查一次」）
       ② 对话区：画像助手陪你聊（一次一个问题，不替本人定分工）
       ③ 「整理到招募表单」→ 三栏预览（招募标题 / 项目想法 / 希望队友参与）
          → 逐栏勾选 →「填入表单」→ 还能改 → 最后「确认发布」才公开
```

**两个智能体怎么配合**：网站当中间人，两个智能体不互相调用。

| 谁 | 干什么 | 范围由谁定 |
| --- | --- | --- |
| 比赛助手（A） | 只回答"这场比赛的要求"（赛道方向 / 提交要求 / 人数规定），带来源 | 服务端按页面上的比赛 ID 锁定，**不采信模型说出的比赛名** |
| 网站 | 把「比赛要求 + 主画像 + 当前表单」拼成一段喂给画像助手 | 主画像按当前登录身份读 |
| 画像助手（B） | 负责和用户聊、负责写三栏文案；比赛事实只依据网站给的那段，不自己补规则 | 会话按比赛分开（`recruit:<比赛ID>`） |

- 一次「和 AI 一起完善」只问 A 一次（同一身份 + 同一场比赛**缓存 30 分钟**），点「重新查一次」才再查。
- **规则是依据、建议是建议**：A 的话以「比赛助手 · 依据」的卡片单独呈现（带引用文件名），不混进 B 的气泡。
- **主画像只用来理解本人**：不会被这份招募整份带走，也不会因为这次讨论被修改；
  预览里会用「可能参考了你主画像里的：…（自己核对一下）」把可能用到的原话列出来——这是网站本机比对的，不是让模型自己说。
- **人数和联系方式自己填**；AI 起草的内容只有点了「确认发布」才公开。
- **面板跟表单一样高、两边对齐**：依据卡是 A 的完整回答，可能很长，但面板**不自己定高**——
  `.recruit-layout` 改 `align-items:stretch`，`#recruit-assist-slot` 设 `position:relative`，
  面板 `.recruit-assist` 用 `position:absolute;inset:0` 填满左栏这一行（行高由表单内容决定，面板的内容不再把行撑长），
  底部跟表单一起收；内容长了就在面板里滚（`overflow-y:auto`）。标题栏 `position:sticky` 钉在面板顶部，「收起」滚下去也点得到；
  面板里只留这一条滚动条（`.recruit-assist .chat-list` 不再自己滚一层）。打开面板时停在最上面先看依据，
  新回复、三栏预览出来时才滚到最新一处。手机宽度（≤1000px）单列铺开，面板改成 `max-height:70vh` 自己滚。
- **输入框一律 `autocomplete="off"`**（提问框 / 画像 / 招募表单）：演示时不再弹出浏览器替你存下的历史输入
  （浏览器自己的「保存的信息」气泡属于浏览器行为，站点只能关掉触发；已存下的旧记录要在浏览器设置里清）。
  登录页保留正常的账号 / 密码自动填充。

接口：`POST /api/recruit/brief`（问 A，带缓存）、`POST /api/recruit/chat`（B 陪聊）、
`POST /api/recruit/draft`（B 只出三栏 + 本机算出画像命中）、`POST /api/recruit/reset`（清空这段对话）。**都不落库。**

## 八、职责分工（这句话放 PPT）

| 谁 | 负责 |
| --- | --- |
| **智能体 A（比赛助手）** | 比赛资料理解、规则问答、资格逐项核对、有限比赛分析 |

> 确定性操作仍由普通系统完成。"**

## 十、数据与平台现状

**新表（4 张，已实现并带测试）**

```sql
users(account PK, kind email|phone, password_hash, salt, name, owner_id, created_at)
profiles(owner_id PK, payload, visibility private|public, updated_at)
```
