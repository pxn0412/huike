## 1. 接口层（`server.py`，6 组）

全部放在 `do_GET` / `do_POST` 现有分支后面，**风格与现有分支一致**。

### 1.1 画像（**AI 生成 ≠ 保存画像**；草稿只在前端状态，不建草稿表）

```text
GET   /api/profile
      → {'profile': {...} | null, 'visibility': 'private'|'public',
         'updated_at': str|null, 'public': {...} | null}     # public 只在 public 时非空

POST  /api/profile/organize          # 只整理，不落库
      body {'message': '用户这一轮说的话'}
      → {'draft': {...}, 'changes': ['新增"做过演示视频"', ...], 'question': '…' | ''}
      · 服务端要把【当前已保存画像】拼进发给智能体的消息里（格式见 2.4）
      · 智能体返回的两段（【画像草稿】【本次修改】）解析成 draft / changes
      · 还没有画像时，已保存部分留空

PUT   /api/profile                   # 用户点「确认并保存」才调用
      body {'payload': {...}}        # 就是前端展示的那份草稿，允许用户改过
      → {'profile': {...}, 'visibility': ..., 'updated_at': ...}
      · payload 为空 → 400「画像里还没有内容，先写点东西再保存。」

PATCH /api/profile/visibility
      body {'visibility': 'public'|'private'}
      → {'visibility': ...}          # 没存过画像 → 400
```

**不需要** `confirmation_token`、草稿表、版本历史 —— **用户点击"确认并保存"这个前端动作就是确认事件**。

### 1.6 资格核对（**不改智能体调用，只加渲染数据**）

`/api/ask` 返回里追加：

```json
{"eligibility": [{"state": "satisfied|unsatisfied|not_specified|missing",
                  "item": "专业条件", "detail": "官方明确\"专业不限\"", "source": "通知 第 1 页"}]}
```

解析规则（写成纯函数，**可单测**）：
- 只解析回答里以 `✅ ❌ ⚪ ❓` 开头的行；
- 每行格式：`符号 状态词 项目：说明 [来源：xxx]`，来源缺失则 `source=''`；
- 解析不出任何一行 → `eligibility = []`，前端退回普通回答展示。

**实现要点**

1. **草稿只在前端**：`state.profileDraft`（+ `state.profileChanges`），刷新即丢；`profiles` 表只有"已确认画像"。
2. `POST /api/profile/organize` 的请求里，服务端拼给智能体的消息格式**必须**是：

```text
【当前已保存画像】
· 做过什么：…
· 本人负责：…
· 希望参与：…
· 正在学习 / 希望尝试：…

<用户这一轮说的话>
```

（没保存过就只发用户那句话；这样 B 才会"只改本次、其余保留"。）

3. 解析智能体返回：`【画像草稿】` 与 `【本次修改】` 两段 → `draft` / `changes`；
   若回答里还有追问（没有草稿段）→ `draft` 为空、把追问放进 `question`，前端只显示追问。
4. 渲染时把 `changes` 显示成"**本次修改**"小块（例：`· 做过什么：新增"做过演示视频"`），
   用户能看到 AI 只动了哪些地方。
5. **不出现**技能等级/熟练度/星级（见 1.1b）；用户明确自述要原样保留。
6. 保存成功后提示「已保存」，并保留"允许展示"开关状态；开关单独调 `PATCH`。
7. 页面顶部固定那句免责文案：「以下内容由本人填写或确认，不代表学校认证」。

| 第一次没有画像 | 用户说经历 → B 追问"你本人主要负责什么" |
| AI 整理 | 形成**简洁三类画像草稿**（不是简历、没有技能等级） |
| 用户确认 | 只有点「确认并保存」才真正写库；刷新前草稿丢了没关系 |
| 再次进入 | 能读回刚才保存的画像 |
| 修改画像 | 只改本次要求的部分，**其余条目原样保留**，界面显示"本次修改" |
| 公开开关 | 开启后招募页能展示；关闭后**立即**不展示 |

> 补充实测（平台侧已完成，可作为验收对照）：
> ① "跟教程做过一次 Vue，写成精通" → **拒绝升级**；
> ② "我精通 Python，三个项目后端都是我写的" → **忠实保留为本人自述**；
> ③ 带【当前已保存画像】追加一条 → 只新增该条，其余原样保留并列出【本次修改】。

**第 2 步做完后第 3 步就好接了**：比赛页发现缺个人信息 → 直接读这份画像；
缺信息 → 调 B 生成补充草稿 → 用户确认 → 回到比赛助手继续回答。
