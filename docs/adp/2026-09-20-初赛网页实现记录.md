# 初赛网页实现记录

## 本轮范围

以用户最新口头确认覆盖旧任务书：只填写显示名称；不区分学生/老师，不做身份页面、退出登录、关注比赛和“我的比赛”。已有 follows 表和旧角色数据保留兼容，但不接入口。新上传资料的角色默认为 user。

## 已实现

- 画像：已确认卡片、AI 澄清与整理、手动编辑、待确认草稿、本次修改、确认保存、读取。草稿仅在当前标签页内存里存在，刷新丢弃；整理接口不保存画像。（**晚：画像页已改成"先对话再整理"，对话落库；公开开关已删除**）
- 画像固定五项文本：major（专业）、grade（年级）、experiences（做过什么/本人负责什么）、participation（希望参与什么）、learning（正在学习/希望尝试什么）。保留本人贡献和学习状态，不做等级或评分。
- 继续修改时带上已保存画像和当前草稿；没有返回的字段从当前草稿保留；“本次修改”由服务端比较实际字段生成。格式无法解析则展示回复，不生成可保存草稿；可用手动编辑处理。
- 比赛页：读取已确认画像提供给比赛助手，原始问题独立用于本地检索；提供四态资格卡片、同比赛招募计数、招募入口、就地补充画像入口。保存画像后由用户继续提问，不自动发送或发布。
- 招募：广场、我的招募、比赛筛选、发布、详情、编辑、结束/重新开启、删除（详情页与「我的招募」卡片上都有删除）、联系方式。只有发布者能修改；返回公开数据时移除内部 owner_id。
- ~~展示画像须同时满足画像公开和该招募勾选展示。~~ **2026-09-20 晚已删除**：主画像不再对外展示，招募详情只展示招募本身的三栏（项目想法 / 希望队友参与 / 联系方式）。
- 姓名只用于展示，归属仍由当前浏览器的匿名 Cookie 决定；改变姓名不等于切换账户。

## 接口

```text
GET  /api/profile
GET  /api/profile/chat           画像对话记录（老的在前）
POST /api/profile/chat           {text, draft?} → {messages, reply, draft?, changes?}：只回话，不整理
POST /api/profile/draft          {draft?} → 网站发起的整理任务，只出草稿
POST /api/profile/chat/reset     清空对话 + 重置这个身份的画像会话
POST /api/profile/save           {payload}，仅由确认按钮触发
POST /api/profile/visibility     {visibility: private|public}
GET  /api/recruitments?competition_id=... 或 mine=1
GET  /api/recruitments/<id>
POST /api/recruitments/create
POST /api/recruitments/update
POST /api/recruitments/delete
GET  /api/competitions/<id>/summary
POST /api/ask                    附加 eligibility / recruit_hint
```

写操作的归属只用 self.owner_id，正文中的 owner_id 不参与判断。匿名首次访问自动取得 Cookie，因此不是“没填写名字就没有 owner_id”。名称只在上传/发布入口要求填写，不增加认证体系。

## 主要文件

- `website/demo.py`：画像输入与输出契约、草稿整理、资格解析、比赛问答上下文。
- `website/server.py`：接入接口；沿用 GET/POST。
- `website/store.py`：复用现有存储方法；增加招募发布者显示名；原问题与模型上下文分开；上传不再要求选角色。
- `website/static/demo.js`：画像/招募页面与交互。
- `website/static/app.js`、`index.html`、`final.css`：原页面整合与样式。

### 2. 登录 / 注册页（邮箱 / 手机号）

- **登录页**（`#login-page`，全屏卡片）：**「登录 / 注册」两个 tab**，同一张卡片切换，不做路由。
  - 登录 = 邮箱或手机号 + 密码；注册 = 再加「显示名称」+「确认密码」（两次不一致前端当场拦下）。
  - 没注册过的账号去登录 → 后端明确回「这个账号还没注册，先去注册一个吧。」（**不再替用户自动建号**）；
    注册重复 → 「这个邮箱或手机号已经注册过了，直接登录吧。」两条提示串成一个闭环。
  - 侧栏底部是「显示名称 + 退出登录」。
- **后端**：`users` 表（`account PK, kind, password_hash, salt, name, owner_id, created_at`）；
  `POST /api/auth/register`、`POST /api/auth/login`、`POST /api/auth/logout`、`GET /api/auth/session`；
  `Store.register()` / `Store.login()` / `Store.user_by_owner()` —— 注册只创建、登录只校验，共用规范化与加盐逻辑。
- **密码**：pbkdf2-hmac-sha256 + 随机盐，20 万次迭代，标准库实现，**不存明文**（测试断言库里搜不到明文）。
- **账号就是身份**：登录成功后把身份 Cookie 换成账号绑定的 `owner_id`，
  所以换台电脑登录同一账号，画像 / 招募 / 上传资料都还在。
  注册时**绑当前浏览器身份**：升级前匿名存过的东西不会丢。
- **真门禁**：除 `/api/status` 与 `/api/auth/*`，其余 `/api` 一律 401（不是前端遮一层）。
- 去掉了旧的自选身份弹窗（姓名 + 学生/老师那套）与 localStorage 自报身份。

### 5. 画像页改成"先聊清楚，再整理"（2026-09-20 晚）

原来的画像页只有一条路：写一段字 → 点「请 AI 整理」→ 出草稿。每一轮都被当成一次整理任务，
用户想问"什么算项目经历"也会被硬塞进画像。现在拆成两层：

| 区 | 行为 |
| --- | --- |
| 对话区 | 输入框 + 「发送」，双方消息**落库**（`profile_messages` 表），刷新和换台电脑登录都还在；「清空对话」只清记录并重置这个身份的画像会话 |
| 草稿区 | 点「整理成画像草稿」才生成；之后还能接着聊、接着改；「确认并保存」才写正式画像（不变） |

后端把返回拆成两路：**`reply` 永远有值**（模型这轮的话 → 有草稿没话时的兜底句 → 彻底没话时的兜底句），
**`draft` 只有整理时才给**。`/api/profile/chat` 的指令明确写着"这是日常对话，不是整理任务，不要输出草稿"；
`/api/profile/draft` 的指令写着"这是网站发起的整理任务"，并按平台提示词的四个标题传
`【当前已保存画像】``【当前编辑草稿】``【对话记录】``【本轮用户消息】`。

两条兜底规则（平台提示词还没改成"只在被要求时出草稿"时也不会丢内容、不会互相打架）：

- 聊天时模型仍塞了草稿：**草稿区空着就收下**（内容别丢），**正在改草稿就不覆盖**，只在回复里加一句提示。
- 「本次修改」由我们自己按底稿算，不看模型在 `【本次修改】` 里写了什么（真机实测它写"无"）。

模型草稿里 `做过什么：` 与 `本人负责：` 是两个标签，会合并进同一个栏目并保留「本人负责：」前缀，不会互相覆盖。

真机实测（真服务 + 真智能体，跑完删账号）：聊一句 → `reply` 是"这个课程短片是什么主题的呀？"、`draft` 为空、
画像仍是 `None`；点整理 → `{"experiences": "参与过一个课程短片\n本人负责：剪辑"}` + `新增"做过什么 / 本人负责什么"`；清空对话后记录为空。
