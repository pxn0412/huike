# 学生竞赛画像 v1：字段与确认规则（冻结稿）

> 2026-09-20 定稿。上级依据：`00-整体产品逻辑.md`、`02-学生竞赛画像.md`、
> `03-智能组队匹配.md`、以及 Agent v0.1 边界（只做比赛理解与画像整理）。

## 0. 本版明确不做（越界即返工）

| 不做 | 说明 |
| --- | --- |
| 团队缺口诊断 | 不推断"你们缺什么角色/什么能力的队友" |
| 队友推荐 / 排序 / 能力评分 | 招募页只按字段筛选，判断留给学生 |
| AI 生成招募需求 | 招募帖由学生自己写（03 属普通产品功能，另做） |
| 按专业推断技能 | 专业 ≠ 会什么 |
| 自动核验技能 | 作品链接只是"本人提供"，系统不核验、不据此评分 |
| 联系方式进核心画像 | 发布招募时单独填写、单独勾选公开；能看画像 ≠ 能看联系方式 |

**允许的唯一"推断"**：把「官方要求」与「画像已记录」逐条并列，由人判断。示例：

```text
官方要求：需要提交演示视频
画像已确认：你做过视频剪辑
结论：这项经历可能与材料准备相关（是否够用由你们判断）
```

画像没有记录时 → 只说「画像中没有相关记录」，**不许**写成"你们缺一个做视频的人"。

## 1. 页面闭环（7 步）

```text
进入「我的竞赛画像」
→ ① 填少量结构化信息，或直接用自然语言描述
→ ② AI 只追问必要信息（一次 1-2 个问题）
→ ③ AI 生成画像草稿
→ ④ 用户逐项修改
→ ⑤ 用户明确点击「确认并保存」
→ ⑥ 用户单独选择是否允许对外展示
→ ⑦ 生成可查看的画像卡
```

## 2. 结构化字段（初赛版冻结 —— **不是简历**）

```text
专业 / 年级          ← 只作背景，一行

做过什么 ｜ 本人负责什么     ← 核心，可多条；每条都要写清"本人负责的部分"
希望参与什么                 ← 方向或角色
正在学习 / 希望尝试什么      ← 保留"正在学 / 跟教程做过 / 想试试"这类限定
```

- **禁止**出现技能等级、熟练度、星级、评分、"了解/精通/能独立完成"这类档位
  （会滑向"AI 能力评分"，与 `02-学生竞赛画像.md` 口径冲突）。
- 用户**明确自述**要忠实记录：他自己说"我精通 Python"→ 记为本人自述，
  **AI 不得升级，也不得反过来降级**。
- 全部内容都是本人自述；系统不认证、不核验、不打分。
- **AI 生成 ≠ 保存**：草稿只在前端，用户点「确认并保存」才写库（无需草稿表/确认令牌）。


项目经历（可多条）
  项目名称
  本人具体负责什么            ← 必填，含糊时只追问这一项
  使用过的工具
  产出或作品链接（可选，标注"由学生本人提供"）

比赛经历（可多条）
  比赛名称
  本人具体贡献

希望尝试
  方向或角色

每周可投入时间（可选）
```

- **不使用"能带人做"作为固定等级**：它容易被读成系统给出的能力认证。
  学生想表达可以自己写"曾带领小组完成…"，但仍是**本人自述**。
- 每条技能/经历都带来源标记：`本人自述`。

## 3. 智能体硬约束（7 条）

1. 不根据专业推断技能；
2. 不把"正在学"改成"已经会"（掌握状态只能按学生原话就近落档）；
3. 不把团队成果全部归到本人（只写"本人负责的部分"）；
4. 经历描述含糊时，只追问"你本人具体负责什么"；
5. 先生成草稿，不直接落库；
6. **没有明确确认凭证，不允许保存**；
7. 保存后修改 → 回到草稿态，需重新确认；对外展示是**独立开关**。

## 4. 状态与数据表

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `profile_drafts` | AI 整理出的草稿（未确认） | `owner_id`、`payload`(JSON)、`updated_at` |
| `profiles` | 已确认画像 | `owner_id`、`payload`(JSON)、`confirmed_at`、`content_hash`、`visibility`(private/public)、`published_fields` |
| `profile_confirmations` | 确认凭证 | `owner_id`、`content_hash`、`confirmed_at`、`note` |

状态机：

```text
(空) --AI 草稿--> draft --用户点「确认并保存」--> confirmed(private)
confirmed --改内容--> draft（原确认失效）        confirmed --开开关--> public
public --关开关--> confirmed(private)
```

- `content_hash` = 画像内容的哈希：**确认的是哪一版内容**，改一个字就失效，必须重新确认。
- 对外展示的字段白名单（不含联系方式）：专业、年级、技能（含自述标记）、项目经历（本人负责部分）、
  比赛经历、希望尝试、每周可投入时间、**学生自选公开的联系方式**（单独勾选）。

## 5. 接口（本地网站）

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/api/profile/draft` | 传自然语言或表单字段 → AI 整理出草稿（不落库为正式画像） |
| POST | `/api/profile/confirm` | 带确认意图（`confirmed: true`）+ 内容 → 落库、发确认凭证 |
| POST | `/api/profile/visibility` | 单独开关：`public` / `private`，可传要公开的字段与联系方式 |
| GET | `/api/profile/me` | 读自己的画像（草稿 + 已确认） |
| GET | `/api/profiles` | 招募页用：**只返回已授权公开**的画像（默认过滤联系方式） |

## 6. 智能体在这条链路里只做三件事

1. 把学生的话整理成**结构化草稿**；
2. 信息含糊时**追问本人负责什么**（一次 1-2 问）；
3. 把「官方要求」与「画像已记录」**并列呈现**（个人准备提示，不下结论）。

不做：推断缺口、推荐队友、排序打分、代写招募需求、任何形式的资格判断。

## 7. Demo 脚本（照抄即可演示）

```text
用户：我会一点 Blender，做过 AIGC 短片，代码一般，之前参加过课程项目。
AI  ：在 AIGC 短片中，你本人主要负责什么？
用户：负责部分画面生成和剪辑。
AI  （草稿）：
  技能：
  - Blender：正在学习（本人自述）
  - AIGC 画面生成：有项目实践（本人自述）
  - 视频剪辑：有项目实践（本人自述）
  项目经历：AIGC 短片
  本人负责：部分画面生成与剪辑
用户：点「确认并保存」→ 画像卡生成 → 单独打开「允许对外展示」
```

## 8. 待确认的 3 个小点

1. 技能掌握状态就三级（正在学习 / 了解 / 能独立完成）——确认不加"能带人做"？
2. 对外展示的默认状态：**默认不公开**（学生自己开）——确认？
3. "比赛经历"独立成一组（比赛名称 + 本人贡献），还是并进"项目经历"？我建议独立，因为招募页要按比赛筛。
