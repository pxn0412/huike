# 比赛资料过滤与新智能体接入

## 当前已经接通的范围

网站上传时根据届次、全称和简称提示可能存在的比赛；用户选择已有比赛，或明确确认创建不同比赛。比赛空间仍是一场比赛一个入口，不增加赛道选择器。

网站问答先从本地 `chunks` 取原文，必须属于当前 `competition_id` 且资料为 `current`；问题明确指向某个赛道时，保留通用原文和该赛道原文，排除其他赛道专属片段。赛道判断以问题本身为准，即使当前库里还没有该赛道资料，也不能退回检索另一赛道。混合多个赛道、无法拆清的一块在单赛道问题中不作为专属依据。模型只收到筛选后的片段，返回的引用还要与片段逐字匹配。原文件不因切块或过滤改变。

当前共用知识库里的已发布 ADP 对话接口没有通过请求级过滤实测，直接扫描它的旧二维码仍可能检索整库。网站因此不把该接口的回答作为已隔离的回答。上传资料仍会进入 ADP 知识库，供以后新智能体使用；两条路径不能混称。

## 新智能体接入顺序

1. 新智能体的输入明确为用户问题、网站确认的比赛 ID、当前用户允许使用的原文片段、必要的近期问答。它不能自行改写比赛 ID，也不能把其他比赛的知识库召回作为依据。
2. 网站保留筛选责任：`Store.search(competition_id, question)` 是现有入口，未来可换成服务端带比赛标签的云端检索；无论检索来自哪里，都要先验证比赛归属、赛道适用范围、资料状态，再把片段交给新智能体。
3. 若让新智能体自己使用 ADP 知识库，先在测试应用验证真实对话是否按每次请求的比赛标签过滤。仅 `SearchKnowledge` 能过滤而对话接口不能过滤，不算通过；此时应由网站检索并给新智能体传入证据，且新智能体的回答环节不得再次无条件检索共用知识库。
4. 新智能体回答后，服务端核对引用的文档 ID、片段原文和范围；任一来源不属于当前比赛或当前问题允许的赛道，整条结论不展示。没有可核对原文时直接说明资料不足。
5. 若仍需要“扫码直接进入 ADP 应用”，必须单独解决扫码入口没有网站比赛 ID 的问题：让二维码先进入网站的比赛页面，或验证独立应用/知识库的隔离方案。不能拿网站过滤的测试结果证明旧二维码安全。

新旧通知局部更新是下一独立阶段：保留原文件，确认具体变更条款和适用范围后，检索当前有效条款；不能靠整份文档的上传时间直接覆盖旧通知。

## 接入前仍需确认的边界

- 当前赛道识别对「AI智能体应用赛 / PBL项目开发赛」有明确规则，其他比赛优先使用资料归属时确认的赛道文字。新智能体上线前，应为每场有多赛道的比赛建立稳定赛道 ID 与别名表；页面仍不必增加赛道下拉框。无法确定归属的片段不应被强行判成某个赛道。
- 网站过滤与旧 ADP 二维码互不等价。旧二维码若还要给用户使用，需改为进入网站比赛页，或者单独验证平台对话层的真正隔离。
- 当前 `document_status=current` 仅排除整份已撤下或被替代的文档，尚未实现“新补充通知只更新旧通知的部分条款”。
