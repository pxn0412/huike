# 校园竞赛服务平台：整体产品逻辑

更新时间：2026-09-17。暂用名称，正式名称待定。本版统一最新功能范围；具体页面与实现方案尚未确定。

## 项目定位

帮助想参加校园竞赛的学生完成“发现比赛 → 看懂要求 → 整理个人经历与意愿 → 浏览或发布招募 → 自行联系队友”的参赛准备。

慧科杯是我们提交作品的比赛，校园竞赛是产品服务的业务场景。产品不限定为只服务本届慧科杯。最终以网页呈现；用户倾向PBL项目开发赛，正式报名赛道尚未确认。

## 已确认的功能范围

| 模块 | 核心作用 | 输出与衔接 |
| --- | --- | --- |
| 01 竞赛信息理解与问答 | 基于比赛资料解释规则、回答问题、按需拆解交付要求 | 有来源的回答、重要未知项及必要的准备建议 |
| 02 学生竞赛画像 | 帮助学生表达做过什么、本人贡献、参与意愿与学习状态 | 本人填写或明确认可、可编辑且可选择展示的画像 |
| 03 队伍招募 | 学生自行发布招募及联系方式，浏览并自主选择 | 招募列表、详情、允许展示的画像和发布者公开的联系方式 |

保留基于画像的比赛推荐，帮助不知道参加什么比赛的学生发现机会。03全程不用AI；已取消缺口分析、AI推荐队友、自动组队和定向采集。不扩展站内申请、站内聊天、社交社区、学习规划或项目协作管理。

## 比赛资料来源与公共发布

比赛资料仅由学生和老师上传，不进行爬取或定向采集。上传后默认仅本人使用，上传者身份不代表资料已经官方认证。

上传者申请公开 → 指定维护者核对申请资料的来源、关键规则和可公开范围 → 通过后进入公共比赛集合，供其他学生问答及比赛推荐使用。未申请公开的资料不进入审核范围，个人画像与问答记录不随比赛资料公开。

记录来源、比赛届次、适用赛道、资料时间与核对状态。公开不代表所有字段均已确认；关键条件未知时，不能将比赛作为已确认可报名的推荐。维护者具体人选与核对尺度待定。

## 用户及职责

- 学生与老师：上传比赛资料，可申请公开或补充更新资料。
- 指定维护者：核对公开申请，维护公共比赛信息。
- 参赛学生：理解比赛，填写或确认画像，选择允许展示的内容，浏览招募并自行联系。
- 招募发布者：自行填写招募与联系方式，编辑内容，并在结束招募时更新状态。

## 完整流程

入口A，已有目标比赛：选择可访问的比赛或上传文件 → 了解关键要求并提问 → 按需填写或复用画像。

入口B，尚无目标比赛：填写简要经历与意愿 → 形成本人认可的画像 → 从公共比赛集合获得比赛推荐及依据 → 自主选择并进一步了解规则。

需要队友时：学生自行发布招募并公开联系方式，或浏览已有招募 → 查看招募详情及获准展示的画像 → 通过公开联系方式自行沟通 → 双方自行商定是否组队及如何分工。发布者可手动关闭招募。

查看联系方式不代表已经联系、达成组队或完成官方报名。系统不设置站内申请、接受或拒绝流程，也不自动追踪站外沟通结果。学生不需要队友时，无需进入招募流程。

## 比赛推荐与AI边界

比赛推荐结合官方资格、时效以及学生经历与意愿，区分“符合资格”和“符合兴趣”。画像不足时仅补问必要内容；缺少可推荐比赛时说明覆盖范围。过期比赛可用于学习，不列为当前可报名比赛。

“比赛寻找学生”指在产品中呈现合适的比赛，不代表替学生报名。通知渠道与频率尚未确定。

AI用于01的资料理解、问答与辅助分析，以及02的经历澄清和画像整理，并支持比赛推荐。03仅保存和展示学生提交的信息，不生成招募内容、不分析团队缺什么人、不推荐候选人、不评分或分配角色。

## 信息真实性与可见范围

- 比赛回答区分资料事实、有依据的直接推导和AI辅助分析，保留来源与适用范围。
- 资料不足时回答已知部分，说明未知；学生无法补充时停止重复追问。
- 原文提取错误、个人身份变更和转述规则更新按不同依据处理；公共信息修正由维护者核对。
- 画像不收集佐证材料、不作能力认证或评分。本人认可不等于系统认证真实性。
- 画像保留“部分参与、正在学习、希望尝试”等限定，03只展示本人允许公开的当前内容。
- 招募发布者主动填写并确认公开自己的联系方式，其他学生据此自行联系；不自动公开账户中的联系信息。

## 最小演示闭环

建议演示：上传真实比赛资料 → 查看关键要求并完成一次有来源的问答 → 整理并确认画像 → 发布含联系方式的招募 → 另一名学生浏览详情和获准展示的画像 → 查看联系方式自行联系。

另外展示基于画像发现比赛的入口，以及一次资料确实不足时的处理。只收录一场比赛时，应如实展示单场适配分析，不能宣称已完成多场优选。模拟学生、比赛和联系方式须标明模拟，不虚构真实联系或组队成效。

## 如何判断有用

检查学生是否能理解比赛要求和回答依据、确认画像忠实表达本人情况、从招募中看懂项目与需求并找到联系入口。真实效果需要试用反馈支持，不能用虚构匹配分数、联系次数或组队结果代替验证。
