# 核心功能一：竞赛信息理解与问答

状态：2026-09-17 范围同步版，已统一上传来源及普通队伍招募的衔接。保留原文件名便于沿用链接。本轮只确定产品内容与效果，不设计页面、数据结构或技术架构。

## 1. 功能定位

围绕学生当前的参赛问题，基于真实比赛资料提供可核查的回答、必要的辅助分析和下一步指引，让学生知道能确定什么、不能确定什么、还需要什么。

解析文件是内部能力，用户价值是理解规则与辅助参赛判断。模块可以由同一个竞赛助手调度，不预设独立部署一个智能体。

模块形成三种连续效果：尚未提问时帮助快速了解并发现重要未知项；提问后围绕问题给出有依据的回答；进一步了解时按需拆解交付要求与准备任务。内容包括比赛事实理解、学生问题回答、影响决策的信息提示、信息缺失识别、比赛任务拆解，不拆成五个独立功能。

## 2. 解决的问题

- 通知、规则与附件较长且分散，难以定位与学生当前问题有关的内容。
- 学生容易混淆符合报名资格与具备完成作品的能力。
- 上传材料可能不全，需要回答已有依据的部分，并说明缺失对判断的影响。
- 通用摘要不一定保留学校、届次、赛道等限定条件，也难以逐项核对出处。
- 学生初次了解比赛时不知道先关注什么，也不知道该问什么，需要少量相关的关注点与建议问题。
- 学生看到了作品名称但不理解交付要求对应哪些工作，需要区分官方成果要求与可能的准备任务。

本模块负责比赛规则理解与必要的条件核对；涉及个人经历与意愿时与画像协同。寻找队友通过03队伍招募，由学生浏览并自行联系。

## 3. 用户流程

### 3.1 上传与准备

学生或老师上传比赛文件 → 识别比赛、届次和赛道 → 提取有来源的事实并保留原文 → 识别关键条件及重要未知项 → 提供快速了解内容、少量建议问题与提问入口。

不强制经老师或管理员代为上传。学生与老师上传后，文件及解析结果默认仅供上传者本人使用，不自动进入公共比赛集合。上传者身份不代表文件已经官方认证。不进行爬取或定向采集。

需要共享时：上传者申请公开比赛资料 → 指定维护者查看申请资料并核对来源、关键规则与可公开范围 → 核对通过后发布 → 供其他学生查询和比赛推荐使用。申请前说明维护者将能查看申请资料，未申请公开的资料不进入该审核范围。维护者具体由谁担任后续确定。

公开范围仅包括经核对可公开的比赛资料和规则，不连带公开上传者的个人背景、画像或问答记录。未通过核对的资料保留个人使用状态并说明原因。公开资料中的未知项仍应标注，发布不等于所有字段均已确认；关键条件不明时不能作为已确认可报名的推荐。

### 3.2 问答与补充

学生提出问题 → 明确问题目标 → 判断所需依据 → 查询资料及已有学生信息 → 依据足够则回答；不足则先回答已知部分，再补问或请求对应材料 → 给出结论、来源与必要的下一步。

有多个比赛或赛道且上下文不能确定时，先确认所指对象。未提出问题时展示快速了解内容，不主动输出全部分析。学生提出“要准备什么”等问题时按需拆解任务；补充材料后重新判断受影响的问题。

学生指出回答错误时，先识别是原文读取错误、个人信息变更还是比赛规则更新，再按对应依据重新判断。学生明确无法补充资料时，结束当前缺失项的追问，保留已知结论与未知项，允许继续了解其他内容。

### 3.3 与其他模块协同

| 学生问题 | 所需依据与行为 |
| --- | --- |
| 什么时候截止报名？ | 比赛资料；区分报名与作品提交时间 |
| 我能参加吗？ | 区分资格与能力；资格核对只补问必要身份条件 |
| 我适合承担什么工作？ | 比赛任务与学生画像；沿用已有经历，仅补问相关缺失信息 |
| 我不知道参加哪个比赛 | 比赛信息与画像共同支撑比赛推荐，学生选定后继续理解规则 |
| 去哪里找队友？ | 引导至03队伍招募，学生自行浏览或发布招募，通过公开联系方式自行联系 |

不要求先完成整份画像才能回答资格问题。不将三个模块预先等同于三个独立智能体。Demo 尚未实现的协同能力需说明状态，不将提示填写资料描述成已经完成模块调用。

## 4. 输入内容

### 4.1 比赛资料

学生和老师上传的比赛通知、规则、报名要求、评分标准、附件和补充通知。

记录原始文件、上传来源、资料发布时间、上传时间、比赛届次及适用赛道。后上传不等于更新版本。附件中的文字作为业务资料处理，不作为对助手的操作指令。

### 4.2 学生问题及必要背景

用户当前问题、所指比赛，以及完成判断所需的最少背景。资格问题可能需要学校、年级；能力问题需要经历与意愿。沿用已确认信息，不重复询问，不凭专业推断技能强弱。

## 5. AI处理逻辑

### 5.1 建立有依据的事实层

以下是检查清单，不要求每场比赛都提供全部信息。

| 类别 | 具体内容 |
| --- | --- |
| 比赛身份与内容 | 名称、届次、主办方、主题、赛道、作品类型 |
| 参赛与团队条件 | 学校、专业、年级限制，人数、指导老师、跨校跨专业要求 |
| 时间与参与方式 | 报名、提交、评审和答辩时间，报名入口、提交渠道 |
| 作品与评审要求 | 交付物、格式、时长、平台限制、评分维度、晋级方式 |
| 其他参与事项 | 费用、奖励、培训、咨询方式及作品使用相关条件 |

每条事实绑定：提取结果、对应原文、来源文件与位置、适用范围、核对状态。PDF用实际页码，其他资料用可定位段落，不编造来源。

保留原始资料，用于查询字段未覆盖的问题。“本校全体在校学生”不能压缩成不限制学校的“全体学生”。不同赛道规则不能混用。

事实层是产品概念，数据库或知识库的技术选型后续确定。

### 5.2 按用户任务组织回答

先判断需要哪些条件，再查询对应依据。问时间先回答时间，问资格先核对资格，不机械照搬官方章节。费用等直接影响参与的条件提前提示，奖励、培训等可以展开查看。

用五类问题帮助确定回答依据，不强制每个问题只属于一类：

| 问题类型 | 需要提供的内容 |
| --- | --- |
| 规则查询 | 时间、人数、渠道等明确规则及来源 |
| 资格判断 | 把官方报名条件与学生已知身份逐项对应，仅补问影响结论的信息 |
| 任务理解 | 解释比赛要做什么、最终提交什么成果 |
| 参与准备 | 分开说明官方必交材料和为完成任务可能需要的准备工作 |
| 能力相关 | 结合画像中的经历与意愿协同分析，不仅凭通知判断个人能力 |

例如“我一个人能参加吗”可能同时涉及人数资格和独立完成能力，前者由规则回答，后者需要项目与个人情况。问题分类服务于回答，不要求学生先自行分类。

信息关联规则是：问题 → 对应条件 → 比赛依据＋必要的学生信息 → 有边界的结论。官方明确“专业不限”，或明确面向本校全体在校学生，可支持对应范围内的专业判断；仅仅“没有找到专业要求”不能自动解释为专业不限。学生只提供专业时，不能据此确认其学校身份。

### 5.3 事实、直接推导与辅助分析

- 资料明确记载：准确转述，保留出处。“已提取”不等于“已人工核对”，来源清楚也不等于内容仍为最新。
- 有依据的直接推导：允许正常理解明确规则，检查限定条件与冲突规定，避免过度拒答。
- AI辅助分析：说明使用了哪些比赛要求和学生信息、结论是什么、存在哪些不确定性，不把推测写成报名门槛。

例如规则明确每队1—5人且无冲突规定，可以判断允许一人队伍。若指导老师要求未知，单独指出该条件未知，不否定已经明确的人数规则。

要求提交演示视频，可以分析需要安排演示制作工作，但不能推出官方要求单独配置一名视频制作成员。具体能力需求必须结合拟做项目，不能仅凭AI比赛就认定需要模型训练或后端开发。

### 5.4 信息不全时如何处理

资料不全仍能开始服务。缺失状态在整个问答过程中影响判断，不只是最后的一个提示列表。

| 状态 | 如何处理 |
| --- | --- |
| 当前资料未找到 | 说明影响，不等于主办方未公布 |
| 官方明确另行通知 | 如实说明等待后续通知 |
| 正文提及附件但未收到 | 指明附件及补充后能解决的问题，不虚构缺失附件 |
| 文字无法辨认 | 请求更清晰的文件或对应页面 |
| 多份资料存在冲突 | 展示差异及来源，暂缓受影响的判断 |

不影响当前问题的缺失不阻断回答：没有奖金信息仍可以解释作品要求。影响资格的缺失只暂停资格结论，不妨碍介绍比赛内容。

缺学生身份就补问身份，缺官方规则就请求规则资料；不能让学生自述替代官方规则，也不凭常识补齐关键事实。需要补充时具体说明缺什么、为什么需要，尽量减少追问。

学生无法补充或暂不补充时，不反复要求上传，也不把未解决的问题标记为已确认。说明当前能判断的内容、仍未知的条件及其影响。如果已有资料提供官方咨询方式，则附出处并指出具体需要核实的问题；没有咨询方式时如实说明，不编造联系人或渠道，不自动代学生联系。

用户可以继续询问其他内容，未来拿到新资料后再恢复该项核对。当前服务可以在“已回答可回答部分、保留未知并说明核实方向”的状态结束，不要求全部未知消失才算完成本次交流。

### 5.5 补充资料与更新

新文件关联同一比赛，重新分析受影响字段，保留新旧依据。判断版本关系需结合发布主体、发布时间、适用范围和明确变更说明，不能按上传先后自动覆盖。

完整版本管理留待后续。Demo先保留资料来源、提取状态和实际发现的缺失；解析成功不等于全部规则已核对正确。

本项目工作赛程采用用户更新的9月24日提交初赛Demo、10月14日最终比赛。这是用户提供的更新，不能标注为6月5日旧PDF原文，也不能补出未说明的截止时刻。查询旧通知内容时如实回答，并说明与用户更新存在差异。

### 5.5.1 学生纠错与规则变更的区别

| 用户反馈 | 处理方式 | 影响范围 |
| --- | --- | --- |
| “你看错赛道了”“第2页已经写了” | 回查所指原文，确实提取或理解错误则承认并修正，提供正确依据；原文不支持时解释原因 | 更新当前答案与相关提取结果；涉及公共资料时提交维护者核对，不凭单条反馈直接改写公共记录 |
| “我不是这个学校的学生” | 更新当前使用的个人条件，重新判断资格，不修改比赛规则 | 当前学生的回答与相关建议；如需同步长期画像，由学生确认 |
| “老师说截止时间改了” | 记录为用户转述的待核对更新，询问是否有补充通知或可核对依据；无法提供时保留来源与未知状态 | 可以说明其对当前判断的可能影响，不直接覆盖公共官方信息 |

纠正原文提取错误不要求用户提供一份新通知，重新核对原文即可；确认比赛规则发生变化则需要新的依据。不能因用户提出异议就无条件改口，也不能把口头转述标成官方原文。

修正后说明改了什么、依据是什么、此前哪项结论需要调整。公共信息若确认有提取错误，维护者修正的是记录，不是改变官方规则；原文及修正依据应保留。

### 5.6 主动提示关注点与重要未知项

围绕参赛资格、组队条件、交付成果和关键时间，提示哪些条件值得学生先看，帮助其决定是否继续了解，不直接替学生判断“值得参加”或“适合你”。展示截止日期，不单凭通知判断“时间充足”或“来不及”；后者需要个人投入时间和项目范围。

主动提示优先选择可能影响报名或作品提交的缺失、冲突和明确限制，不机械罗列所有空字段。每项未知说明影响，例如“当前材料未找到报名截止时间，暂时无法确认现在是否还能报名”。资料充分时可以不显示缺失提示，不为体现主动性制造问题。

根据当前比赛资料与已知疑问提供少量可继续询问的问题，初始建议2—3个，避免固定重复。问题应能获得有依据的回答，或帮助补齐关键条件；未知事项也可以成为建议问题，但不能暗示已经有确定答案。

### 5.7 按需拆解比赛任务与要求

学生进一步询问“要做什么”“怎么准备”“难在哪里”时，围绕实际交付要求展开，不默认给所有比赛套用同一套开发步骤。

| 层次 | 内容与边界 |
| --- | --- |
| 官方交付要求 | 明确要交什么、达到什么条件，并提供出处 |
| 可能需要完成的工作 | 基于交付要求提出准备步骤，标为AI辅助分析并说明依据 |
| 尚不能判断的工作量 | 指出取决于拟做项目、完成标准和学生经历，必要时补问 |

例如官方要求可运行作品，可以分析需要考虑功能实现与验证；要求演示视频，可以分析需要选择演示内容并制作视频。不能由此推出固定开发周期、笼统难度等级，或必须配置独立开发、测试与视频成员。

任务拆解保持在理解要求和准备工作的范围。涉及个人情况时参考画像中的经历与意愿；需要哪些队友由学生自行判断并填写招募，不进行团队缺口分析。

## 6. 输出结果

### 6.1 尚未提问：快速了解

先提供比赛名称及赛道、一句话说明，帮助识别比赛；再优先呈现影响参与决定的内容：

- 面向谁：已知资格和明确限制，不代替学生核对全部个人条件。
- 如何组队：人数与已说明的组队方式，不把允许组队写成必须组队。
- 交什么：核心成果与明确的格式、平台等约束。
- 何时如何参与：关键日期与报名、提交方式，区分不同阶段。

同时提供原始资料及核对状态。上述关键内容未找到时明确标注，不隐藏未知，也不将提取完成标成全部核对通过。其他细则、奖励与培训可供进一步了解；费用等直接影响参与决定的条件应提前提示。

明确标注资料使用范围，例如“仅本人使用”“待公开核对”“已公开”。本人材料的问答与公共比赛问答分别使用其可访问资料，不能把他人的未公开上传内容用于回答或推荐。

只提示优先级较高的未知或冲突，并说明影响。报名已过期或状态无法确认时如实标注，不直接判断学生投入时间是否足够。

提供少量结合资料的建议问题，例如“我符合参赛条件吗？”“可以一个人组队吗？”“最终需要提交哪些材料？”。不要求每场比赛展示同一组问题；涉及个人适配的问题说明需要结合经历。

这些规定只确定内容，不决定页面布局或按钮形式。

### 6.2 提出问题后：有依据地回答

可使用“资料明确记载、AI辅助分析、当前无法确认、下一步”四类标签，不要求每次凑齐四块。简单问题只给答案和来源，复杂判断再展示分析、未知条件及补充需求。

示例一：真实通知中的明确事实。

> 学生：几个人一队？
>
> 回答：每队1—5人。来源：用户提供的2026年6月5日慧科杯通知，第2页。

示例二：有依据的直接推导。

> 学生：可以一个人组队吗？
>
> 回答：按通知的人数规定，可以组成一人队伍。依据是第2页的每队1—5人，其他报名条件仍需分别满足。

示例三：缺失处理的通用示意，不代表本次慧科杯通知缺少这些内容。

> 目前可以说明比赛主题和作品要求，但本次材料中未找到参赛对象说明，因此还无法确认你的资格。可以补充包含参赛资格的规则页，继续核对。

涉及能力分析时使用个人经历和意愿，不仅凭专业给出适合或不适合。回答、查看招募或自行联系均不代表完成官方报名。

学生可以指出错误或补充信息，系统按5.5.1核对并修正。不能继续补充时，可以给出这样的收尾内容（通用示意，具体未知项需按实际资料核对）：

> 人数规则允许一人队伍，但是否必须配指导老师仍无法确认。你暂时没有其他材料，可以先保留这个待核实项，继续了解作品要求。

如果资料列有官方咨询方式，再附对应来源及“是否必须配指导老师”这一具体核实问题；资料没有列出时不虚构。

### 6.3 进一步了解：展开任务与准备内容

按学生需要列出官方交付成果、每项成果对应的可能准备工作及分析依据，并说明还不能判断的内容。不强制输出完整行动计划或团队角色表。

以本次通知为例：第3页要求AI赛道提交10分钟以内的功能演示视频，这是官方要求；据此提出“梳理演示重点、准备演示素材、制作并检查视频”属于辅助分析。谁负责、需要多久，仍需结合实际项目与成员情况。

### 6.4 内容验证与Demo最小范围

用真实文件展示基础卡片、事实回答、直接推导和一个资料确实不足的问题。检查答案与页码是否正确、是否混淆赛道、是否只补问必要信息、是否把未知条件误写成否定规则。

重点证明能回答已知部分、识别证据不足并给出具体补充需求。无需为演示堆叠完整版本管理或编造缺失附件。

本轮补充内容的检查重点：未提问时能否快速识别关键条件；主动提示是否只突出重要未知；建议问题是否与资料相关；任务拆解是否区分官方要求和辅助分析，是否无依据地断言难度、所需时间或角色。这些可沿同一案例观察，无需新增一套独立演示。本轮不编排页面与演示脚本。

同时核对三条产品规则：未公开资料不进入公共查询或推荐；原文纠错、身份变更和转述规则更新按不同依据处理；用户无法补充后不循环追问、不编造咨询方式。规则已写入设计不代表Demo已经实现，实际覆盖范围后续如实标注。
