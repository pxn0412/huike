# 慧科网站与资料问答：开源复用初筛

调研日期：2026-09-19。

范围：用户要求先寻找可复用资料，暂停网站实现扩展。本轮使用网页检索读取 GitHub 仓库、官方文档及部分源码；没有克隆、安装、运行这些候选，也没有验证混元接入。网页可读不代表本机 Git 拉取/推送可用。个别原始文件获取失败，不作反复重试。

## 推荐结论

优先验证 PDF.js 的原文件预览与页码跳转；参考 Youtu-RAG 的文件管理、知识库归属与问答页面组织。Docling 作为文档解析候选，用真实中文比赛 PDF 验证后决定。已有腾讯 ADP 工作流保持为待接通的 AI 服务，不因寻找组件自动切换平台。

当前 website/ 是初步自写代码，尚未完成测试和真实 AI 接入，不能算可交付 Demo。候选调研后再决定替换哪些模块，不删除已有工作。

## 1. PDF.js：优先复用

- 仓库：https://github.com/mozilla/pdf.js
- 许可证：主项目 Apache-2.0，见 https://github.com/mozilla/pdf.js/blob/master/LICENSE 。分发时保留相关许可及依赖声明。
- 已读源码：https://github.com/mozilla/pdf.js/blob/master/examples/learning/prevnext.html
- 源码确认：通过 getDocument 加载 PDF，getPage(num) 获取指定页，render 将页面渲染到 canvas；示例处理前后翻页及并发渲染排队。
- 适配：做全站通用的 PDF 侧边预览组件，接收 document_id 与真实 PDF 页序号。后端负责原文件访问，证据片段负责页码。PDF.js 不负责判断比赛归属或回答问题。
- 验收：点击引用后打开对应文件/页；连续切换引用正确；缩放后清晰；中文字体与扫描页正常显示。没有坐标时先不承诺高亮原文。

## 2. Youtu-RAG：最相关的整站流程参考

- 仓库：https://github.com/TencentCloudADP/youtu-rag
- 许可证：MIT，已读 https://raw.githubusercontent.com/TencentCloudADP/youtu-rag/main/LICENSE 。
- 已读中文 README：https://github.com/TencentCloudADP/youtu-rag/blob/main/README_ZH.md
- 已核对目录：https://github.com/TencentCloudADP/youtu-rag/tree/main/frontend/rag_webui/pages
- 已确认存在的文件：file-management.html、knowledge-base.html、knowledge-base-detail.html、chat.html、chunk-viewer.html、ocr-viewer.html。
- README 描述：原生 HTML/CSS/JavaScript 前端，提供文件上传、知识库关联、问答和预览；PDF/OCR 相关功能需要配置相应服务。
- 可借鉴：上传资料、关联知识库、查看片段与问答的页面分工。不能直接把“知识库”改名为“比赛”就认为完成业务适配。
- 必须补：Competition 届次与身份、用户确认后正式提交、新旧通知保留、限定比赛/赛道检索、原文引用和当前时间规则。
- 限制：仅确认目录与文档，尚未完整审阅这些页面源码。整体系统包括我们不需要的长时记忆与多种 Agent；不建议直接整套引入。位于 TencentCloudADP 组织并不证明能直接调用用户已有的 ADP 云端工作流。

## 3. Docling：文档解析候选

- 仓库：https://github.com/docling-project/docling
- 许可证：代码 MIT，模型许可需要单独核对。
- 文档：https://docling-project.github.io/docling/concepts/docling_document/
- 已查看类型源码入口：https://github.com/docling-project/docling-core/blob/main/docling_core/types/doc/document.py
- 官方说明支持 PDF 结构识别、OCR、结构化文档及来源位置信息。类型入口包含 ProvenanceItem；位置字段与转换输出仍需通过样本实测。
- 适配：解析输出映射到 EvidenceChunk，保留文本与位置，不能只导出 Markdown 后丢弃来源。AI 再基于解析结果提取比赛身份草稿。
- 验收：普通 PDF、中文扫描 PDF 各一份；核对人数、日期和页码是否准确；记录本机模型下载量、运行耗时与内存。
- 限制：支持 OCR 不代表现有比赛扫描件必然识别正确；需要运行和抽样核对。

## 4. assistant-ui：聊天界面备选

- 仓库：https://github.com/assistant-ui/assistant-ui
- 许可证：MIT（README 标明）。
- 已读 README：https://github.com/assistant-ui/assistant-ui/blob/main/README.md
- 提供 React 聊天组件、流式显示、附件与自定义后端适配。
- 适配：若决定采用 React，可复用聊天部分；仍需自己编写比赛上下文传递、确认页和引用卡片。
- 当前 website 为原生前端，引入该库需要切换/增加 React，不是直接复制一个文件即可。暂不为聊天外观单独迁移技术栈。

## 5. CloudBase Agent UI：腾讯生态备选，不能混淆平台

- 仓库：https://github.com/TencentCloudBase/cloudbase-agent-ui （仓库显示 MIT）。
- 官方 React 文档：https://docs.cloudbase.net/ai/agent-ui/agent-ui-react
- 文档展示 CloudBase 环境 ID、SDK、云开发模型或 Agent 接入；所查 React 文档明确列出 React 17/18 适配约束。
- 判断：适合采用 CloudBase 服务的项目。用户目前用的是 ADP 画布，不能把 CloudBase botId 当作 ADP 应用 ID，不能承诺直接复用现有工作流。先核对 ADP 的实际调用协议，再决定是否使用。

## 6. RAGFlow：检索和引用流程参考

- 仓库：https://github.com/infiniflow/ragflow （Apache-2.0）。
- 官方 README 提供文档解析、分块可视化、引用与 API，列出 CPU 至少 4 核、内存至少 16 GB、磁盘至少 50 GB 等自托管要求。
- 可借鉴资料切块检查与引用展示。当前最小 Demo 不优先引入整套基础服务，避免重复搭建已有 ADP 知识库能力。

## 下一步验证顺序

1. PDF.js：在本地单独验证指定页预览。
2. 核实 ADP 是否返回可用的文件 ID、片段和位置，以及自动上传/索引/按比赛过滤接口。若已满足，不重复部署另一套 RAG。
3. 只有 ADP 原文定位或解析不足时，再运行 Docling/OCR 样本验证。
4. 参考 Youtu-RAG 页面分工实现我们的确认流程，不复制其不属于 v0.1 的 Agent 和记忆功能。

本报告是复用候选和验证计划，不是已集成清单。
