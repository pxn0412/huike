# 多格式资料上传与结构切块实施记录

目标：按用户授权直接实现 PDF、PNG/JPEG/WebP/BMP/TIFF、Word（docx/doc）、TXT/Markdown 上传，沿用确认归属后入库的产品流程。

设计：原文件始终保存；统一解析入口返回正文与来源类型，PDF 保留真实页码，图片标图片序号，Word/文本标正文位置、不伪造排版页码。DOCX 按正文顺序读取段落和表格；旧 DOC 使用本机 Word 转换，未安装时提示另存 DOCX。扫描识字复用 Windows OCR。

切块：标题层级、段落/清单/表格优先，超长正文按句子后按长度拆开；表格分块重复表头；保留来源范围；不把未知赛道称为“两赛道通用”。本地和知识库使用相同切块结果。新规则作用于新上传资料，不自动重传或删改云端旧资料。

实施顺序（本地串行执行）：
- [x] 写解析、伪装格式、Word 表格顺序、图片 OCR 降级与切块回归测试，确认当前失败。
- [x] 实现统一解析、原文件与文本预览接口，沿用内容哈希判重。
- [x] 实现结构切块及来源标注，接通本地索引与知识库输出。
- [x] 更新上传和查看原文页面。
- [x] 隔离真实 AI/知识库的测试，运行现有回归，浏览器验证及真实本机 OCR/Word 转换验证。

2026-09-28 验证记录：145 项单测通过；check-formats.cjs 中 DOCX、PNG、PDF、TXT 的选择文件、侧栏预览、原件内容及确认入库通过。真实 Windows OCR 能返回文字（仍可能有识别误差），真实 Word DOC→DOCX 转换通过。代码检查发现内容控件遗漏，已补充正文和表格内控件回归并修复。所有测试使用临时数据库，平台写入被替换，不污染正式知识库。

验证边界：不向正式知识库写入测试资料；不修改用户数据库；不承诺复杂排版完全还原。损坏、加密、不支持格式明确报错；OCR 不可用时保存原件并显示不可检索原因。
