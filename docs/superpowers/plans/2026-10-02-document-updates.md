# 比赛资料更新实施计划

**目标：** 同一比赛的新资料可新增、部分更新、整体替换或保留冲突；原文件始终可追溯，上传顺序不决定有效性。

**授权：** 用户已确认方案，并要求先删除现有比赛资料后实施。保留账号、画像和桌面原件。

**设计：** AI 仅提出对比项，每项绑定新旧原文片段、范围与环节。服务端验证逐字引用；用户选择才产生更新记录。默认检索使用生成的当前证据片段，原始 chunks/pages 不被修改。知识库同步以当前证据为上传内容，并跟踪切换状态；失败或尚未学习完成不得称作已更新。

- [x] 清空本地和云端比赛资料，验证保留账号与画像。
- [x] 比较接口：读取临时上传及当前比赛原文，AI 生成可验证的新旧变化。
- [x] 上传确认页：关系四选一、原文双侧入口、逐项更新勾选。
- [x] 保存关系与部分变更，生成当前检索证据；防止过期对比、串比赛、无来源更新。
- [x] 云端同步：新证据准备好后停用旧检索文件；失败状态明确，原件和历史保留。
- [x] 展示已更新项目及来源，测试未变规则与历史引用。
- [x] 检查并启动网站，不自动上传测试资料。

**边界：** 不增加赛道选择器，不以学生/教师自选身份赋权。当前问答仍使用现有调用方式；本轮更新证据选择和引用，不再次切换问答架构。
